# intent_MILEAGE — пробег не больше 400 000 км, иначе review

Собрано по итогам интервью Grill Me (2026-09-24). Пометки источников:
«интервью» — ответ заказчика, «код: <файл>» — текущее поведение в репозитории.

## 1. Замысел

Добавить в расчёт решения по заявке проверку пробега авто: если пробег больше
400 000 км, решение не может быть approve — оно понижается до review. Решения
review и reject, полученные по остальным правилам, понижение не затрагивает
(интервью).

Дополнительно — трактовка пустого пробега: если пробег не указан (поле
отсутствует, null или пустая строка), это ошибка валидации, заявка до расчёта
решения не доходит. Сегодня отсутствие поля даёт ошибку, но null и пустая
строка молча превращаются в «0 км» (код: backend/src/Domain/ApplicationValidator.php:43–46) —
это исправляется в рамках задачи (интервью).

## 2. Зачем

Сейчас решение по заявке зависит только от LTV: пробег в расчёт решения не
подаётся вовсе (код: backend/src/Domain/DecisionEngine.php:30 — на входе
только LTV). Автомобиль с идеальным LTV и пробегом 499 000 км автоматически
получает approve. Задача — не выдавать автоматическое одобрение заявкам с очень
большим пробегом: свыше 400 000 км решение должно быть review вместо approve
(интервью, исходная формулировка задачи).

## 3. Constraints

1. Порог 400 000 км, граница включительная: ровно 400 000 км проходит без
   понижения; review — с 400 001 км (интервью).
2. Правило понижает только approve → review. Пример из интервью: заявка с
   высоким LTV (reject по деньгам) и пробегом 450 000 км получает reject,
   а не review (интервью).
3. Пустой пробег — ошибка валидации (интервью); текущее расщепление поведения
   (отсутствие поля → ошибка, null/пустая строка → молча 0 км) — код:
   backend/src/Domain/ApplicationValidator.php:43–46.
4. Существующие проверки не меняются:
   - пробег — целое от 0 до 500 000 км; потолок 500 000 остаётся (код:
     backend/config/rules.php:23, `max_mileage_km`; интервью — вариант «сузить
     потолок до 400 000» не выбран);
   - пороги решения по LTV: approve ≤ 62, review ≤ 85, reject > 85 (код:
     backend/config/rules.php:44–45);
   - прочие проверки заявки — VIN, год, стоимость, сумма, срок — без изменений
     (код: backend/config/rules.php).
5. Диапазон 400 001–500 000 км — валидная заявка; её решение — review, если по
   LTV было approve, а не ошибка валидации (интервью, пп. 1–2; код:
   backend/config/rules.php:23).
6. При решении review одобренный лимит — 0; пониженная с approve заявка лимит
   не получает (код: backend/src/Domain/AssessmentService.php:39).

## 4. Open questions

Сверено с исходной формулировкой задачи («иначе решение review»): буквальное
прочтение допускало «любое решение → review», включая reject → review; в
интервью явно выбран вариант «понижается только approve, reject сохраняется»
(пример: LTV-отказ + пробег 450 000 км → reject). Расхождений, требующих
решения заказчика, не осталось. Все вопросы из docs/plan/plan_MILEAGE.md
закрыты интервью:

1. Граница 400 000 км — закрыт (интервью): включительно, review с 400 001.
2. Приоритет reject против правила — закрыт (интервью): reject сохраняется.
3. Пустой/неизвестный пробег — закрыт (интервью): ошибка валидации; молчаливый
   каст null/пустой строки в 0 км исправляется в задаче.
4. Диапазон 400 001–500 000 км — закрыт (интервью): review, не ошибка валидации.
5. Поле причины review в ответе — закрыт (интервью): не входит.
6. Зона действия — закрыт (интервью: сверх правила ничего не выбрано; решение
   считается в одном месте — код: backend/src/Domain/DecisionEngine.php).

Открытых вопросов нет.

## 5. Не входит

- Поле причины review в ответе расчёта (интервью).
- Изменения фронтенда, пояснения решения на форме (интервью).
- Снижение валидационного потолка пробега 500 000 → 400 000 (интервью).
- Задача LOAN-12 — лимиты по возрасту авто (интервью).
- Изменение порогов LTV и остальных проверок заявки (код:
  backend/config/rules.php — остаются как есть).
