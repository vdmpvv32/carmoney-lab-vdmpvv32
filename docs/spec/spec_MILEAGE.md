# spec_MILEAGE — пробег не больше 400 000 км, иначе approve понижается до review

Спека по `docs/intent/intent_MILEAGE.md`. Пометки источников: «интервью» —
интервью Grill Me 2026-09-24, «код: <файл>» — текущее поведение в репозитории.

## Входит / не входит

**Входит:**

- Проверка пробега в расчёте решения: пробег > 400 000 км понижает approve до
  review (интервью).
- Трактовка пустого пробега (поле отсутствует, null, пустая строка) как ошибки
  валидации; исправление молчаливого каста null/пустой строки в «0 км» (интервью;
  код: backend/src/Domain/ApplicationValidator.php:43–46).

**Не входит:**

- Поле причины review в ответе расчёта (интервью).
- Изменения фронтенда, пояснения решения на форме (интервью).
- Снижение валидационного потолка пробега 500 000 → 400 000 км (интервью).
- Задача LOAN-12 — лимиты по возрасту авто (интервью).
- Изменение порогов LTV и остальных проверок заявки — VIN, год, стоимость,
  сумма, срок (код: backend/config/rules.php — без изменений).

## Требования и критерии приёмки

### REQ-MILEAGE-01 — порог понижения 400 000 км, граница включительная

Если пробег больше 400 000 км, решение approve понижается до review. Ровно
400 000 км понижения не вызывает; review — с 400 001 км.
Источник: интервью; intent, constraints п. 1.

- **AC-MILEAGE-01** (REQ-MILEAGE-01). Given заявка с LTV ≤ 62 и пробегом
  399 999 км. When рассчитывается решение. Then approve.
- **AC-MILEAGE-02** (REQ-MILEAGE-01). Given заявка с LTV ≤ 62 и пробегом
  400 000 км. When рассчитывается решение. Then approve (граница включительная).
- **AC-MILEAGE-03** (REQ-MILEAGE-01). Given заявка с LTV ≤ 62 и пробегом
  400 001 км. When рассчитывается решение. Then review.

### REQ-MILEAGE-02 — понижение действует только на approve

Правило понижает только approve → review. Решения review и reject, полученные
по остальным правилам, понижение не затрагивает.
Источник: интервью (пример: LTV-отказ + пробег 450 000 км → reject); intent,
constraints п. 2.

- **AC-MILEAGE-04** (REQ-MILEAGE-02). Given заявка с LTV > 85 (reject по LTV)
  и пробегом 450 000 км. When рассчитывается решение. Then reject, не review.
- **AC-MILEAGE-05** (REQ-MILEAGE-02). Given заявка с LTV в диапазоне
  62 < LTV ≤ 85 (review по LTV) и пробегом 450 000 км. When рассчитывается
  решение. Then review (не меняется на reject и не дублирует понижение).

### REQ-MILEAGE-03 — диапазон 400 001–500 000 км валиден

Пробег в диапазоне 400 001–500 000 км проходит валидацию; это заявка со
решением review (при LTV ≤ 62), а не ошибка валидации. Валидационный потолок
500 000 км остаётся без изменений.
Источник: интервью; intent, constraints пп. 4–5; код: backend/config/rules.php:23
(`max_mileage_km` = 500 000).

- **AC-MILEAGE-06** (REQ-MILEAGE-03). Given заявка с пробегом 500 000 км.
  When проходит валидация. Then ошибок валидации по пробегу нет.
- **AC-MILEAGE-07** (REQ-MILEAGE-03). Given заявка с пробегом 500 001 км.
  When проходит валидация. Then ошибка валидации по пробегу (потолок 500 000).

### REQ-MILEAGE-04 — пустой пробег — ошибка валидации

Если пробег не указан (поле отсутствует, null или пустая строка), это ошибка
валидации: заявка до расчёта решения не доходит. Текущее молчаливое
преобразование null/пустой строки в «0 км» исправляется.
Источник: интервью; intent, constraints п. 3; код:
backend/src/Domain/ApplicationValidator.php:43–46.

- **AC-MILEAGE-08** (REQ-MILEAGE-04). Given заявка без поля `mileage`.
  When проходит валидация. Then ошибка валидации по пробегу.
- **AC-MILEAGE-09** (REQ-MILEAGE-04). Given заявка с `mileage = null`.
  When проходит валидация. Then ошибка валидации по пробегу, пробег не
  трактуется как 0 км.
- **AC-MILEAGE-10** (REQ-MILEAGE-04). Given заявка с `mileage = ""` (пустая
  строка). When проходит валидация. Then ошибка валидации по пробегу, пробег
  не трактуется как 0 км.

### REQ-MILEAGE-05 — лимит при пониженном решении

При решении review одобренный лимит — 0; заявка, пониженная с approve по
пробегу, лимит не получает.
Источник: intent, constraints п. 6; код:
backend/src/Domain/AssessmentService.php:39.

- **AC-MILEAGE-11** (REQ-MILEAGE-05). Given заявка с LTV ≤ 62 и пробегом
  400 001 км, пониженная до review. When формируется ответ. Then одобренный
  лимит = 0.

### REQ-MILEAGE-06 — существующие проверки без изменений

Существующие проверки заявки не меняются: пробег — целое от 0 до 500 000 км;
пороги решения по LTV approve ≤ 62, review ≤ 85, reject > 85; проверки VIN,
года, стоимости, суммы, срока — без изменений.
Источник: intent, constraints п. 4; код: backend/config/rules.php:14–45.

- **AC-MILEAGE-12** (REQ-MILEAGE-06). Given заявка с LTV = 62 и пробегом
  399 999 км. When рассчитывается решение. Then approve (порог LTV 62 —
  включительный, без изменений).
- **AC-MILEAGE-13** (REQ-MILEAGE-06). Given заявка с LTV = 85 и пробегом
  399 999 км. When рассчитывается решение. Then review (порог LTV 85 —
  включительный, без изменений).
- **AC-MILEAGE-14** (REQ-MILEAGE-06). Given заявка с LTV = 86 и пробегом
  399 999 км. When рассчитывается решение. Then reject (порог LTV 85 —
  без изменений).

## Открытые вопросы из intent

Все 6 вопросов из intent закрыты интервью, переносов нет:

1. Граница 400 000 км — закрыт (интервью): включительно, review с 400 001 →
   REQ-MILEAGE-01.
2. Приоритет reject против правила — закрыт (интервью): reject сохраняется →
   REQ-MILEAGE-02.
3. Пустой/неизвестный пробег — закрыт (интервью): ошибка валидации, молчаливый
   каст в 0 км исправляется → REQ-MILEAGE-04.
4. Диапазон 400 001–500 000 км — закрыт (интервью): review, не ошибка
   валидации → REQ-MILEAGE-03.
5. Поле причины review в ответе — закрыт (интервью): не входит (раздел
   «Не входит»).
6. Зона действия — закрыт (интервью: сверх правила ничего не выбрано) →
   требований сверх понижения approve и валидации пробега в спеке нет.

Требований, которых не было в intent, в спеке нет.
